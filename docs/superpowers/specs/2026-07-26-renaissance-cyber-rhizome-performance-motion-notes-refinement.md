## 2. 锁定的设计原则

### 2.1 视觉与性能

- 不在“性能”和“动效是否存在”之间二选一。
- 视觉效果、运动阶段、素材数量和交互反馈不因性能档位被删除。
- 性能档位只可改变内部渲染分辨率、粒子密度和采样频率。
- 只有正在变化、正在被观看或正在被直接操作的层才计算。
- 离屏层暂停；稳定层冻结；指针、触摸、滚动、聚焦、Resize 或重新进入视口会唤醒相关层。
- 高刷新率屏幕不设固定 60 FPS 上限。

### 2.2 解域化—再域化

- 每个主要视觉在首次进入时完成一次明确的“分裂—组装”。
- 完成首次组装后，回滚页面不再把它重置为初始碎裂态。
- 后续只允许由局部交互触发轻微、可逆的再次分裂。
- 慢速指针几乎不扰动物件；快速掠过才短暂打开清晰裂隙，并迅速归位。
- 移动端保留完整叙事，不改成静态缩略图。

### 2.3 文章与图谱

- 两篇文章各有一条隐藏思想主线，行文允许受控漫游，并在结尾回到开头的场景或意象。
- Blog / Notes 不是普通日期列表，而是一张可阅读、可搜索、可进入的根茎索引图。
- 概念关系是主边，标签关系是次边，时间只扰动坐标，不成为中心轴。
- 图的拓扑和大致位置跨刷新保持稳定，节点只做局部持续漂移。
- 相关文章由全文语义向量自动计算，不依赖字面词语完全相同。

## 4. 运行时性能契约

### 4.1 单一调度器

首页和 Blog 图谱分别只能存在一个受控动画调度器。首页现有 Field、fragment、pointer、scroll 和 collision 更新必须汇入同一调度边界，不允许多个互不知情的永久 `requestAnimationFrame` 循环。

调度器维护以下脏标记：

- `viewportDirty`
- `pointerDirty`
- `assemblyDirty`
- `collisionDirty`
- `graphDirty`
- `resizeDirty`

只有至少一个脏标记存在，或可见组件仍处于时间相关的过渡态时，才安排下一帧。组件进入稳定态后清除自己的脏标记。

### 4.2 唤醒与休眠

唤醒来源：

- 可见区进入或离开。
- 滚动位置或滚动方向改变。
- 指针速度越过扰动阈值。
- 触摸拖曳。
- 键盘聚焦或阅读器开闭。
- Resize、DPR 或显示器刷新环境改变。
- `visibilitychange` 后重新进入前台。

休眠条件：

- Hero 完全离开视口。
- Blog 图谱完全离开视口。
- fragment 已达到目标值且速度低于静止阈值。
- 页面进入后台。
- 阅读器打开后，页面背后的 Field、fragment 和图谱不可见。
- Motion 被关闭或 `prefers-reduced-motion` 生效。

使用 `IntersectionObserver` 管理大区块可见性，使用 `ResizeObserver` 使组件局部失效。滚动监听必须是 passive，并在同一帧中先批量读取几何，再批量写入样式，禁止读写交错。

### 4.3 Fragment 更新边界

- 全局 `chapter` 只负责章节语义、配色和整体气氛，不再直接决定每一本书、界面或证据图片的几何拆分度。
- 每个可组装组件拥有自己的进度、状态和 observer。
- 已稳定且不在交互半径内的 fragment 不写 CSS 自定义属性。
- 长期 `will-change` 只在过渡开始前添加，在归位后移除。
- Collision 证据图片退出通用 `[data-rr-fragment]` 弹簧循环，由独立证据链控制。

### 4.4 Canvas / WebGL

- Hero 可见时保持完整 Canvas / WebGL 视觉。
- Hero 离屏后停止绘制，不以透明或遮挡代替真正暂停。
- 生产态不得周期性执行同步 `readPixels()`；诊断采样只能存在于显式 debug 模式。
- Canvas backing size 随 `FIDELITY` 调整，但 CSS 尺寸和构图不变。
- 图像解码、Canvas Resize 和节点重建不得发生在滚动热路径中。
- 固定导航的 `backdrop-filter` 若在目标设备上持续产生重合成压力，应改为视觉近似的半透明实色与细线；不能以删除导航动效作为第一手段。

## 5. `FIDELITY` 控制

### 5.1 可见形式

校准条中保留可见的：

`FIDELITY / AUTO · III · II · I`

它不是“开关特效”，而是采样档位显示与控制。

当前有效档位旁同时显示实测目标频率，例如 `III / 144 Hz`；罗马数字表示档位，Hz 数值表示当前显示环境下的实际采样目标。

### 5.2 默认与记忆

- 每个新标签页会话从 `AUTO` 开始，并重新测量设备。
- `AUTO` 根据真实帧间隔和主线程压力动态选择 `III`、`II` 或 `I`。
- 用户手动选择后，只锁定当前标签页会话。
- 手动选择可以使用 `sessionStorage` 保持同一标签页刷新后的状态；关闭标签页后不保留。
- 返回 `AUTO` 后立即恢复测量与动态调整。

### 5.3 档位定义

首先通过一段稳定的 `requestAnimationFrame` 样本估计当前屏幕原生刷新率 `R`：

- `III`：目标采样频率为 `R`。
- `II`：目标采样频率为 `0.75R`。
- `I`：目标采样频率为 `0.5R`。

不设置固定 60 FPS 上限。高刷新率显示器按其原生节奏工作；II 与 I 只降低内部采样频率。

各档位可以改变：

- Canvas 内部分辨率。
- 粒子或场采样密度。
- 物理积分和视觉采样频率。

各档位不得改变：

- 主要素材数量。
- 分裂、组装、扫描、停留、退隐等运动阶段。
- 指针、触摸和滚动反馈是否存在。
- Blog 图谱的节点、主边和次边。
- 书页与封面的可读终态。

### 5.4 AUTO 稳定规则

- 初次测量不得阻止首屏内容显示。
- 降档以连续超预算样本为依据，避免单次抖动触发。
- 升档使用更长迟滞，避免 III / II / I 来回跳变。
- 档位变化只在安全帧切换，不重置章节、书封和证据链进度。
- Resize、显示器切换或页面从后台恢复后，AUTO 可以重新校准。

## 6. 独立组装状态机

### 6.1 通用状态

Rhizome-Learn 界面、两本书封面和需要组装的视觉均使用组件级状态：

```text
unseen
  → assembling
  → settled
  → disturbed
  → recovering
  → settled
```

状态写入组件自身的 `data-rr-assembly`，不得只存在于不可测试的内部变量中。

### 6.2 首次组装

- 每个组件独立计算自身 bounding box 与视口的关系。
- `unseen → assembling` 在组件进入预备带时发生。
- 组装进度只由该组件的局部进入进度决定。
- 每次页面访问只播放一次首次组装。
- 直接刷新到页面中段时，组件必须从当前几何推导正确状态，不能依赖用户从 Hero 开始滚动。
- Resize 后保留“已首次组装”的事实，只重新计算目标几何。
- 反向滚动不会把 `settled` 退回 `unseen`。

### 6.3 两本书封面

《陌异女性主义》和《平台社会主义》分别拥有独立 observer、局部进度和状态。

硬性终态：

- 当某本封面的中心到达视口下三分之一的起始线，即 `66.7vh` 时，它必须已经完整归位。
- 两本书互不依赖；第一本的进度不能决定第二本的拆分度。
- `settled` 时所有 fragment 满足：
  - `|x| ≤ 1px`
  - `|y| ≤ 1px`
  - `|angle| ≤ 0.1deg`
  - `depth ≤ 0.02`
- 拼缝、重复边和错位文字在正常观看距离下不可见。

### 6.4 局部再分裂

- 只有组件已经 `settled` 后，局部交互才能触发 `disturbed`。
- 慢速指针移动只产生亮度渐变光晕，不产生可辨认的几何错位。
- 快速掠过封面时，裂隙幅度随指针速度增加，但不得破坏书名识别。
- 指针离开或速度下降后立即进入 `recovering`。
- 从最后一次快速扰动到再次满足 `settled` 数值不变量，目标时间不超过 400ms。
- 扰动只作用于被指针经过的局部，不同步震动整本封面。

### 6.5 移动端

- 首次滚入仍播放完整“分裂—组装”。
- 触摸扫过或较高的局部滚动速度可以触发短暂裂隙。
- 松手或速度下降后按同一终态归位。
- 不使用 hover 假象，不因为移动端而删除任何叙事阶段。

### 6.6 Reduced Motion

`prefers-reduced-motion` 或 Motion Off 下直接进入同一 `settled` 几何，不播放连续弹簧和局部裂隙。内容、图片和阅读入口保持完整。

## 7. Collision：可逆横向证据链

### 7.1 结构

Collision 区分为：

- `.rr-collision__traces`：研究线与翻译线的语义轨迹。
- `.rr-collision__evidence`：四份视觉证据的横向序列。
- `.rr-collision__release`：证据链结束后的释放与留白。

四份视觉证据不再作为重叠拼贴，也不再被通用 fragment 状态设为“collision 时永远完全解体”。

### 7.2 桌面滚动

- Collision 进入 pinned 视口。
- 垂直滚轮输入映射为证据链横向进度。
- 向下滚动沿一个方向推进；向上滚动沿同一路径反向播放。
- 反向时连续倒放当前进度，不瞬移、不重新洗牌。
- 用户到达链首或链尾后，垂直滚动自然离开该区。

### 7.3 动态距离

证据链占用的有效滚动距离根据输入速度平滑变化：

- 慢速阅读接近 `3 × viewport height` 的章节长度。
- 常规速度位于中间。
- 快速滚动压缩至约 `1 × viewport height`。

实现时可将上述范围表达为约 `300vh` 至 `100vh` 的滚动轨道。速度映射必须平滑并带迟滞，不能在滚动过程中改变总进度或造成页面跳跃。

### 7.4 单份证据的生命周期

每份证据依次经历：

```text
queued → scanning → revealed → holding → receding → passed
```

- `scanning`：无文字提示的扫描线逐步显影。
- `revealed`：图片完整、可识别、几何归位。
- `holding`：短暂停留，让用户有明确观看窗口。
- `receding`：亮度和显影范围后退，图片退出主观看位。
- 反向滚动严格反演上述过程。

图片本身不显示说明文字、标题、序号或“请继续滚动”。语义 HTML 仍需提供准确的无障碍名称，但不得形成可见图注。

### 7.5 移动端

- 使用原生横向滑动浏览证据链。
- 垂直滚动始终可以离开 Collision，不制造滚动陷阱。
- 横向溢出只存在于证据容器内部，不能增加文档级 `scrollWidth`。
- 向相反方向滑动时反向执行同一生命周期。

## 8. 阅读器与 Top-Layer 光标

### 8.1 根因边界

普通文档层的 `.rr-cursor` 无论使用多高 `z-index`，都不能覆盖 `showModal()` 创建的浏览器 top layer。不得继续用提高 `z-index` 的方式修复。

### 8.2 阅读器光标

- `dialog` 内新增自己的 reader cursor，使它与书页位于同一个 top layer。
- 打开 reader 时隐藏页面层 cursor，并启用 reader cursor。
- 关闭 reader 后销毁或停用 reader cursor，恢复页面层 cursor。
- 如果 reader cursor 初始化失败，必须恢复系统光标；不允许系统光标与自定义光标同时不可见。

Reader cursor 不显示文字，由两层构成：

- 一个高对比的小点。
- 一个随距离衰减、带亮度渐变的柔和光晕。

主题色：

- 《陌异女性主义》：偏酒红、朱砂的渐变光晕。
- 《平台社会主义》：偏青、蓝的渐变光晕。

光标不得遮盖正文笔画；光晕只改变亮度和透明度，不对书页应用模糊。

### 8.3 输入与可访问性

- 鼠标进入图片、滚动区域和关闭按钮时，reader cursor 始终可见。
- 键盘模式继续使用原生焦点环，不用 reader cursor 代替焦点。
- Escape、关闭按钮、焦点陷阱和关闭后的焦点返回保持有效。
- 触屏不显示模拟鼠标，只保留触点光晕。
- Reduced Motion 关闭光晕的追随缓动，但保留高对比位置点。

## 9. Blog / Notes：根茎索引

### 9.1 列表页

`/blog/` 重做为根茎索引图，不再以普通圆角卡片或单纯倒序列表作为主要入口。

视觉分型：

- Research Notes：冷色仪器界面。
- Translation Notes：暖色手稿界面。

图谱规则：

- 文章是可点击主节点。
- 概念关系是主要连线。
- 标签关系是更细、更暗的次要连线。
- 时间只对位置施加轻微扰动，不形成时间轴。
- 节点颜色区分 research / translation，不把类别做成圆角标签。
- hover 或键盘 focus 显示自动正文摘录；click 直接进入文章。

### 9.2 稳定拓扑与局部漂移

- 语义边、标签边和节点身份跨刷新保持一致。
- 构建产物包含固定种子和归一化锚点。
- 节点可在锚点附近持续小范围漂移，边随节点实时重绘。
- 漂移不得改变边的身份、相关文章排序或节点大致区域。
- 图谱可见时运行；完全离屏、页面隐藏或 reader 打开时停止 rAF。
- 图谱重新进入视口后从当前相位继续，不随机重排。
- Reduced Motion 下使用相同固定拓扑和锚点，停止漂移。

### 9.3 语义向量

主要关系使用全文语义向量，而不是仅用正文关键词重合、标签重合或人工关系表。

输入文本至少包括：

- `title`
- `thesis`
- `description`
- 去除导航、脚注编号和代码后的正文

生成规则：

- 使用固定版本的中文／多语种句向量模型。
- 在维护阶段离线生成，不在访客浏览器中请求模型或外部 API。
- 仓库只向前端提供已生成的节点、边、相似度、锚点和内容哈希。
- 同一文本、同一模型和同一版本必须生成确定结果。
- 正文内容哈希变化而图谱产物未更新时，验证命令必须失败。
- 前端不下载完整向量；只消费经过阈值和每节点上限裁剪后的边。

自动相关文章按余弦相似度排序。标签重合可以作为视觉次边和极小的平分项，但不能覆盖语义向量主排序。

### 9.4 编辑元数据

每篇札记保留 Jekyll 原字段，并新增：

```yaml
note_id: stable-ascii-id
note_kind: research | translation
thesis: 一句话思想主线
project_ids:
  - stable-project-id
concepts:
  - canonical-concept-id
```

字段职责：

- `note_id`：稳定节点身份，不随标题改变。
- `note_kind`：决定冷仪器或暖手稿阅读模式。
- `thesis`：参与语义向量和无图形回退，不作为页面醒目标语。
- `project_ids`：建立 Project 与札记的双向入口。
- `concepts`：用于概念名显示、加权搜索和局部子图筛选；不取代全文语义向量。

`date` 保留原发布日期。不得新增“修订日期”显示。

### 9.5 自动摘录

hover / focus 摘录由正文自动生成：

- 选择第一个实质段落。
- 跳过标题、题记、脚注和引用块。
- 去除 HTML 后截取前 120 个中文字符或等价长度。
- 不另写手工摘要。
- 截断时使用省略号，不切断 HTML 实体。

### 9.6 搜索

Blog 文字索引支持全文搜索，权重从高到低为：

1. 标题。
2. `concepts` 中的规范概念词。
3. 标签。
4. `thesis` 与 description。
5. 正文。

搜索结果与图谱同步：

- 文字结果 hover / focus 时点亮对应图节点和相关边。
- 图节点 hover / focus 时定位并点亮对应文字结果。
- 搜索过滤不重新随机布局，只隐藏或弱化不匹配节点。

### 9.7 标签页与分类页

每个 Tag / Category 页面采用上下两层：

- 上部：该集合的局部根茎图。
- 下部：可搜索文字索引。

图与索引双向同步。关闭 JavaScript 后，下方文字索引仍完整可用。

### 9.8 文章页

Research 文章采用冷色仪器阅读模式；Translation 文章采用暖色手稿阅读模式。两者共享结构，不复制插件拥有的 layout。

文章页保留：

- 正文优先的单列阅读宽度。
- 桌面端边注式脚注。
- 移动端文末脚注。
- 页面边缘一条无文字细刻度阅读进度线，随段落逐段点亮。
- 清晰的键盘焦点、选区颜色和外链状态。

文章末尾：

- 取消传统“上一篇／下一篇”。
- 显示语义最接近的相关节点。
- 相关节点沿概念关系继续阅读，不按日期强行线性排列。

## 10. 两篇长文的编辑规范

### 10.1 共同要求

- 每篇 3500–4500 个中文字符，达到可独立发布的长篇随笔体量。
- 保留原发布日期。
- 使用新的标题和 URL，不保留旧 URL，也不设置 redirect。
- 至少三个有实质推进作用的二级标题，但不能写成教学提纲或报告模板。
- 一条隐藏思想主线贯穿全文；段落可以漫游，但每次偏离都应通过意象、问题或概念回到主线。
- 允许第一人称的犹豫、改稿和判断过程，不得编造没有发生过的个人事件。
- 核心术语可以保留在正文；较长原文、出处和补充争论进入脚注。
- 所有引用、理论归属、书目信息和原文必须可核验。
- 明确区分事实、个人判断和仍待验证的设想。
- 结尾不写口号，不总结“研究与翻译最终统一于某物”。
- 两篇之间只通过“地图、异乡、回路、命名”等意象形成暗合，不显式互相引用。
- 正文不得出现“本站只展示”“未展示”“不公开哪些内容”等前端披露说明。

### 15.1 性能与调度
