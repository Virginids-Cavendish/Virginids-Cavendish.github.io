## 1. 项目边界

本轮重做对象是 Virginids 作品集的首页与首页可见的全局壳层，不是全站所有子页面。

实现范围：

- 重做 `_pages/about.md` 的内容结构与视觉叙事。
- 将现有主题导航重新着装为细窄的仪器校准条，但保留主题原有 DOM、搜索、主题切换和移动端折叠行为。
- 增加首页专属 CSS、JavaScript、Canvas/SVG/DOM 动效和内容素材。
- 保留 Projects、Rhizome-Learn、Translation Projects、Blog / Notes、CV 等深层页面作为继续阅读入口。
- 保持 al-folio / Jekyll / GitHub Pages 的构建与部署方式。

本轮不做：

- 不重写主题插件或复制 `_layouts`、`_includes`、`_sass` 等插件拥有的运行时。
- 不把所有子页面一并改造成同等复杂度。
- 不引入 React、Three.js 或新的重型构建链。
- 不在本轮自动提交、推送或部署。

## 2. 设计命题

首页不是一组介绍卡片，而是一台正在运行的研究仪器。

结构层来自文艺复兴手稿、比例尺、铜版画、解剖图谱和古典书页；赛博朋克只作为光、电路、反馈和系统响应层出现。整体应首先被感知为古典知识装置，其次才是未来控制界面。

核心体验关键词：

- Renaissance manuscript
- Dark instrument interface
- Decentered rhizome
- Control and feedback
- Deterritorialization / Reterritorialization
- Living archive
- Uncanny adaptive system

必须避免：

- 普通白底圆角卡片阵列。
- pill 标签堆叠。
- 常见 SaaS dashboard 布局。
- 单一中心、主干、树冠或向外放射的树状 Hero。
- 大面积紫蓝渐变、廉价霓虹和无功能 glitch。
- 只靠纸张纹理营造的静态复古页面。

## 3. 体验目标

首页同时支持两种阅读速度：

- 约 3 分钟的快速浏览：顺着垂直卷轴即可理解身份、研究线、翻译线和联系方式。
- 约 10 分钟的深度探索：通过指针、触摸、聚焦、横向展开和页面阅读态发现更完整的材料。

首屏情绪是冷静、精密、可观察；随着交互积累，系统逐渐开始模仿用户节奏，并呈现轻微侵入感。状态只存在于当前会话，不跨会话追踪。

不提供显式新手教程、热点提示或“点击这里探索”的教学文案。交互应能从视觉反馈中被自然发现。

## 4. 信息与章节架构

页面采用“固定仪器 Hero + 连续手稿长卷”的整体结构。

### 4.1 Calibration Strip / 全局导航

- 复用现有主题导航 DOM，不隐藏或复制导航。
- 视觉上改造成细线、刻度、坐标、序号构成的校准条。
- 保留品牌、页面导航、搜索、明暗主题和移动端折叠按钮。
- 不使用圆角按钮或 pill。
- 导航始终位于 Canvas 和自定义光标层之上，可正常点击和聚焦。

### 4.2 Hero / Dark Instrument

- 首屏高度约为一个完整视口，随后自然露出下一章节。
- Hero 不是树、根系主干或中心神经核，而是无中心、非层级、可从任意边缘进入的 rhizome 场。
- 不使用头像。
- 多条路径从视口边缘进入、交叉、断裂、回环、重新连接并再次离开视口。
- 节点权重接近，不建立唯一视觉中心。
- 古典蚀刻式“不可实现图谱”作为空间底稿；网络、扫描、反馈光作为动态上层。
- 画面包含比例尺、坐标刻痕、测量弧、状态编号和少量控制轨迹。

Hero 必须包含：

- 用户提供原始书法笔迹构成的纵排姓名。
- 哥特体 `Virginids` 字标。
- 极简身份索引与研究坐标。
- 可进入 Projects / Archive / Contact 的文字锚点。

### 4.3 Identity Index / About + Skills

About 与 Skills 不做卡片。

- 使用手稿目录、馆藏索引和仪器读数式的线性排版。
- About 只保留精炼身份与研究兴趣。
- Skills 以编号、坐标、方法和对象组成细窄索引。
- 必须保留课程验证要求中的可检索文字：
  - Hero
  - About
  - Skills
  - Projects
  - Contact
  - Mathematical Modeling
  - Optimal Control
  - Adaptive Learning
  - Project Management

### 4.4 Rhizome-Learn / Research Line

研究线使用青色至绿色电光，运动更机械、可测量、离散。

- 使用真实运行界面截图，不使用抽象信息图替代。
- 截图至少完整、清晰出现一次。
- 在其他状态中，同一截图被切片、错位、重新装配，形成“界面作为知识地形”的效果。
- 快速浏览时可理解项目定位；深度探索时可进入 Rhizome-Learn 专页。
- 页面文案聚焦结构化学习、知识节点、自适应复习、反馈和轨迹，不使用“哪些内容被展示、哪些没有被展示”的说明。

### 4.5 Translation Archive / Translation Line

翻译线使用朱砂、铜墨和旧纸色，运动更接近墨的渗透、拖曳、覆写和干裂。

- 两本书的封面都必须清晰、完整出现一次。
- 封面在章节进入或离开时可分裂成碎片，并重新构成。
- 两本书以不同节奏进入，随后异步缠绕，而不是并排放入两个卡片。
- PDF 正文页既可作为可读页面，也可进入裁切、重叠和错位的展示状态。
- 点击或聚焦正文页时进入完整阅读态，文字必须达到实际可读尺寸。
- 前端不出现素材筛选、展示范围或未展示内容的解释。

### 4.6 Collision Field / 双线交汇

研究线和翻译线保持平行、交叉、分离、再交叉，不由一句总结口号强行统一。

- 青绿的机械反馈线与朱砂的墨迹线在少数节点碰撞。
- 碰撞时才允许出现金色短闪与轻微 glitch。
- 信息密度逐步增加，达到一次受控过载，再迅速释放为大面积留白。
- 书封、书页、界面碎片和蚀刻图谱在此发生“解域化—再域化”，但必须仍可返回可读状态。

### 4.7 Contact / Network Exit

- Contact 不是页尾卡片。
- 网络线穿出视口，暗示系统继续延伸。
- Email 与 GitHub 作为两条明确、可聚焦、可复制的出口信号。
- 保留 `Contact` 文本，以满足语义和课程验证。

## 5. 视觉系统

### 5.1 色彩

基础色：

- `Void Black`：近黑暗室背景。
- `Smoke Black`：面板、玻璃和深层纸影。
- `Bone`：正文、刻度与书法显示色。
- `Old Gold`：碰撞、交汇和关键校准点。

研究线：

- `Research Cyan`
- `Feedback Green`

翻译线：

- `Cinnabar`
- `Copper Ink`

用色规则：

- 古典骨架主要使用黑、骨白、铜和旧金。
- 青绿与朱砂只表示系统状态和内容谱系。
- glitch 色只在交汇或错误反馈中短暂出现。
- 背景在“玻璃仪器”与“纸张手稿”之间切换，不把二者同时铺满所有章节。

### 5.2 形状与容器

- 默认直角或切角，不使用大圆角。
- 内容通过细线、标尺、负空间、裁切和层叠组织。
- 必要的面板使用 `clip-path`、伪元素、错位边框或显微镜载玻片式边缘。
- 标签改为边注、编号、坐标或校准刻度。
- 不用阴影和圆角模拟“高级感”。

### 5.3 字体与姓名

中文正文：

- 以易读的宋体或现代衬线中文字体为基础。
- 标题允许极端尺度、窄行距、纵排与错位，但正文阅读态保持稳定。

英文仪器标签：

- 使用窄体无衬线或等宽字体。
- 只承担状态、坐标、编号和操作反馈，不取代中文叙事。

姓名：

- 视觉姓名使用用户提供的三张原始笔迹，依次为 `閻`、`光`、`鋒`。
- 原图只经过确定性的色阶分离、连通区域去噪、纯黑化和透明背景抠图。
- 禁止用 AI 重写、补笔、平滑字形或伪造跨字牵丝。
- 三字合成只调整缩放、位置和留白，不改变任何笔画。
- 外框笔画不得为了跨字动效产生不符合笔顺的连接。
- 语义文本与搜索信息中保留 `阎光锋`。
- `Virginids` 使用哥特体，与中文书法形成古典双重签名。

书法资产：

- `assets/img/renaissance-rhizome/name-feng-extracted.png`

### 5.4 图像语言

- Hero 底图是菌丝、神经解剖、航路、机械仪器和测量装置的不可能混合体。
- 不出现唯一中心、树干或中心透视消失点。
- 古典图像碎片使用新生成或自有素材，不直接挪用未经处理的历史画作作为主视觉。
- 书封、书页和产品截图保留来源内容的可读性，不用滤镜破坏文字。

## 7. 动效与交互语法

动效由三类输入共同驱动：

1. 自主呼吸：页面在无人操作时仍有缓慢、不同步的生命迹象。
2. 局部探索：指针或触摸改变附近节点、路径、景深和反馈光。
3. 章节变换：滚动触发网络、纸张、书页与界面碎片的重组。

### 7.1 运动物理

基础层：

- 有机、缓慢、非同步。
- 网络像菌丝或组织，而不是电路板 screensaver。

研究线：

- 机械、分段、带采样和误差校正感。
- 节点脉冲不同时发生。
- 路径亮度沿轨迹移动，但速度保持克制。

翻译线：

- 墨迹拖曳、渗透、覆盖、干裂。
- 页面和封面碎片具有纸张惯性，不做普通卡片轮播。

交汇：

- 只在碰撞点出现短促 glitch、旧金闪光和状态回弹。

### 7.2 姓名的解域化—再域化

- 初始状态中姓名可完整辨认。
- 随页面进入运行态，三张原始笔迹可作为独立层轻微错位、遮断或被网络穿过。
- 笔画本身不变形、不补写、不生成新连接。
- 在关键章节或返回 Hero 时重新归位为完整纵排签名。
- 动效改变的是字的空间关系，不是书写本体。

### 7.3 Context Cursor

桌面端使用与情境相关的自定义光标：

- 默认是探针或细十字。
- 靠近可读页面时变成聚焦框或标尺。
- 靠近节点时显示采样范围。
- 不遮挡文本，不替代系统焦点可见性。

触屏不伪造光标，使用触点波纹和局部场响应表达相同逻辑。

### 7.4 声音

- 不使用环境音乐或持续氛围声。
- 只在用户主动触发的交互中提供极轻的反馈声。
- 音频上下文必须由用户手势启动。
- 提供明确静音控制，并记住当前会话内选择。

### 7.5 会话记忆

- 只使用内存或 `sessionStorage`。
- 不跨会话保存交互画像。
- 系统随当前会话逐渐从“临床观察”转为“模仿节奏”，最后产生轻微侵入感。
- 侵入感只通过路径靠近、反馈提前和局部跟随表达，不使用恐吓、闪烁或失控动画。

## 8. 滚动与空间

- 主轴保持垂直滚动。
- 关键章节允许短距离 pinned 状态。
- Rhizome-Learn 和 Translation Archive 可在 pinned 区间产生内部横向或景深位移。
- 不让用户进入无法退出的横向滚动容器。
- 页面总高度控制在浏览器全页截图和移动端内存的安全范围内。
- Contact 结束后不加普通大页脚视觉块；网络线应继续离开画面。

## 9. 移动端

移动端不是静态简化版，而是完整仪器的自适应实现。

- 保留网络、书法、真实截图、封面和页面阅读态。
- 使用触摸位置替代 hover。
- 可在用户授权后使用轻量设备倾斜响应。
- 权限被拒绝或设备不支持倾斜时，触摸与滚动仍能完成全部内容。
- 根据屏幕尺寸、DPR 和运行帧率自适应减少节点数、采样频率和透明层，不删除核心叙事。
- 限制 Canvas 实际 DPR，避免高分屏显存过载。
- 所有文字锚点和阅读态满足触控尺寸与安全区。
- 主题原有移动导航折叠行为必须继续工作。

## 10. 可访问性与降级

- 完整支持 `prefers-reduced-motion`。
- 提供会话内可用的 Motion / Sound 控制。
- Reduced Motion 下保留构图和章节转换，但停止持续漂移、视差和高频反馈。
- Canvas 只是视觉层，核心内容必须存在于语义 HTML。
- 所有图片有准确替代文本。
- 可交互书页支持键盘打开、关闭和焦点返回。
- 文本和控制项满足可读对比度。
- 自定义光标不得隐藏键盘焦点。
- JavaScript 失败时仍能看到姓名、项目、封面、书页、联系方式和深层链接。

## 11. 技术方案

### 11.1 页面与资产

- `_pages/about.md`：语义结构与 Liquid 资产路径。
- `assets/css/renaissance-rhizome.css`：首页视觉系统和响应式规则。
- `assets/js/renaissance-rhizome.js`：网络、滚动、指针、触摸、会话状态和可访问性控制。
- `assets/img/renaissance-rhizome/`：书法、蚀刻图谱、真实界面、书封和书页。

所有 HTML 资产路径通过 Liquid `relative_url` 生成，以兼容站点根路径和测试 baseurl。

### 11.2 渲染栈

采用 Hybrid Canvas/WebGL + SVG/DOM：

- Canvas/WebGL：无中心网络、粒子、局部反馈和大面积动态场。
- Canvas 2D：WebGL 不可用时的确定性回退。
- SVG：比例尺、测量弧、裁切路径和精确连接。
- DOM：所有可读内容、链接、控制和可访问状态。

不引入 Three.js；网络由固定种子生成，避免每次加载和视觉测试出现随机构图。

### 11.3 主题边界

- 保留 `theme: al_folio_core` 与现有插件配置。
- 不新增主题插件拥有的核心目录。
- 不覆盖主题的主 CSS、导航脚本或图标运行时。
- 不隐藏 `#navbar`、`.navbar-toggler`、`.navbar-collapse`、搜索或主题切换控制。
- 首页视觉层不得截获导航点击。

### 11.4 性能

- 桌面端根据 DPR 与帧率调整节点数量。
- 移动端限制实际 DPR 和离屏纹理尺寸。
- 图片提供合理尺寸，非首屏内容延迟加载。
- 首屏姓名、底图与基础 HTML 优先显示。
- 页面进入后台时暂停动画。
- 检测视觉测试稳定器时冻结在确定帧。
- 不用持续 layout thrashing 驱动动画，优先 transform、opacity 和单个渲染循环。

## 12. 文案原则

- 主要叙事为中文。
- 英文只作为仪器标签、方法名、状态码和项目原名。
- 文案不替视觉作总结，不用口号解释“研究与翻译最终统一于何物”。
- 不向前端用户解释素材选择流程、隐私筛选流程或未展示内容。
- 不提供整本 PDF 下载；精选书页 PNG 只作为首页叙事素材与阅读态内容。
- 不使用“这是一个实验性网站”“请探索”等自我说明。
- 保持事实准确，不创造研究成果、出版状态或未完成项目。

首页必须自然包含：

- `阎光锋`

## 13. 验收标准

### 13.1 视觉

- 第一眼不再像圆角卡片作品集。
- Hero 明确是暗室仪器，而不是树、山峰或中心网络。
- 文艺复兴负责结构；赛博朋克只负责光、电路和反馈。
- 用户原始书法可辨认，且没有 AI 补笔或错误牵丝。
- `Virginids` 呈现为哥特体。
- Rhizome-Learn 真实界面清晰出现。
- 两本书的封面均清晰出现。
- 至少若干 PDF 正文页可进入实际阅读态。
- 研究线与翻译线可被区分，也能发生可见交汇。
- 页面经历受控增密、过载与释放。
- Contact 的网络视觉越出视口。

### 13.2 交互

- 自主呼吸、局部探索和滚动变换三类动效均存在。
- 桌面指针、移动触摸和可选倾斜输入均有对应反馈。
- 只有交汇点使用 glitch。
- 姓名能从完整状态解域，再回到可读状态。
- 当前会话内的交互历史会轻微改变系统行为。
- 不需要教程即可完成快速浏览。
- Reduced Motion、Motion 控制与 Sound 控制有效。

### 13.3 技术

- `npm.cmd run verify:assignment` 通过。
- `npm.cmd run lint:style-contract` 通过。
- 主题导航、搜索、明暗切换和移动端折叠正常。
- 页面没有横向溢出。
- 桌面与移动端无不可读、遮挡或焦点陷阱。
- Canvas 使用固定种子并可在视觉测试中冻结。
- JavaScript 失败时核心内容仍可访问。
- 不在公开文本、注释或数据属性中写入本地绝对路径。

### 13.4 验收视口

至少检查：

- 1440 × 1100 桌面视口。
- 390 × 844 移动视口。
- Reduced Motion。
- JavaScript 关闭后的核心内容。
- 键盘导航与书页阅读态。

## 14. 原型阶段允许调整的参数

以下参数由首版视觉原型决定，不构成重新 grill 的阻塞项：

- Hero 节点的精确数量。
- 每个 pinned 区间的持续长度。
- 书页进入过载场的具体页数。
- 三个原始书法字的最终间距与缩放比例。
- 青绿、朱砂和旧金的最终色值。
- 指针影响半径、阻尼和会话演化速度。

调整原则是维持本 spec 的叙事、素材、笔迹真实性、移动端完整性和性能边界。
